# 🌡️ Urban Heat Island Detection and Analysis System
 
A full-stack web application for detecting, analyzing, and visualizing Urban Heat Island (UHI) effects across 9 major Indian cities using Landsat 8 satellite imagery and a **GMM + XGBoost** machine learning pipeline.

> **Dataset:** Google Earth Engine — Landsat 8 Collection 2 Level-2

---

|------|--------------------|---------|

| Ahmedabad | Apr – Jun | 39.61 °C |

Each city uses a **city-specific peak summer date window** instead of a generic full-year range, ensuring the satellite composite captures worst-case UHI conditions.

## ⚙️ Tech Stack
 
| Layer | Technology |
|-------|-----------|
| Satellite Data | Google Earth Engine — Landsat 8 Collection 2 Level-2 |
| Clustering | Gaussian Mixture Model (GMM, n=4, covariance_type=full) |
| Classification | XGBoost (200 trees, learning_rate=0.1, max_depth=6) |
| Model Selection | BIC score across n=2..6 components |
| Backend | Flask + Flask-CORS |
| Frontend | Vanilla HTML + CSS + JavaScript (single `index.html`) |
| Map | Leaflet.js |
| Charts | Chart.js |

## 🧠 ML Pipeline
 
```
Landsat 8 (Google Earth Engine)
        │
        ▼
  Feature Extraction (6 features)
  ┌─────────────────────────────────────────────┐
  │ LST   — Land Surface Temperature (Band 10)  │
  │ NDVI  — (B5 - B4) / (B5 + B4)              │
  │ NDBI  — (B6 - B5) / (B6 + B5)              │
  │ FVC   — Fractional Vegetation Cover         │
  │ MNDWI — (B3 - B6) / (B3 + B6)  [water]    │
  │ NDMI  — (B5 - B6) / (B5 + B6)  [moisture] │
  └─────────────────────────────────────────────┘
        │
        ▼
  Data Cleaning
  (LST: 15–55 °C | NDVI: −0.3 to 1.0)
        │
        ▼
  BIC Score Selection (n=2..6)
  → Picks optimal number of GMM components
        │
        ▼
  GMM Clustering (Gaussian Mixture Model)
  Soft probability assignment — borderline pixels
  handled correctly (fixes K-Means hard-boundary bug)
  Labels ranked by: LST − NDVI×10 (combined score)
        │
        ▼
  XGBoost Classifier (200 trees, sequential boosting)
  Each tree corrects mistakes of the previous one
  Accuracy: 98.5% – 99.6% across all cities
        │
        ▼
  GeoJSON + Stats JSON
        │
        ▼
  Flask API → Leaflet.js Map + Chart.js Charts + Predict Zone UI
```
 
### Why GMM over K-Means
K-Means draws hard boundaries — a pixel is forced into whichever cluster centroid is nearest. GMM computes a probability for each cluster and assigns the pixel to its most likely cluster. This correctly handles borderline pixels (e.g. a cool green area near a hot cluster).
 
### Why XGBoost over Random Forest
Random Forest builds 100 independent trees and averages them. XGBoost builds trees sequentially — each tree learns from the errors of the previous one (gradient boosting). This gives consistently better accuracy on tabular satellite data.
 
### Heat Zone Labels
 
| Zone | Label | Color | Description |
|------|-------|-------|-------------|
| 0 | Low | 🟢 Green | Dense vegetation, low surface temp |
| 1 | Moderate | 🟡 Yellow | Parks / residential green areas |
| 2 | High | 🟠 Orange | Dense residential / mixed urban |
| 3 | Critical | 🔴 Red | Industrial / commercial hotspots |
 
> Labels are **city-relative** — Critical in Mangaluru (coastal, ~39°C) represents a different absolute temperature than Critical in Delhi (~47°C). This makes predictions more meaningful than applying a fixed global threshold.
 
### Features Used
 
| Feature | Bands | Description |
|---------|-------|-------------|
| `lst` | Band 10 | Land Surface Temperature (°C) |
| `ndvi` | B5, B4 | Vegetation health index |
| `ndbi` | B6, B5 | Built-up / urban density index |
| `fvc` | — | Fractional Vegetation Cover (derived from NDVI) |
| `mndwi` | B3, B6 | Water body index — separates water from vegetation |
| `ndmi` | B5, B6 | Moisture index — dry vs wet surfaces |

## 🌐 API Endpoints
 
| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/` | Serves `index.html` |
| GET | `/api/health` | Health check + list of loaded city models |
| GET | `/api/cities` | List all 9 cities with data availability |
| GET | `/api/stats?city=bengaluru` | Dashboard stats (avg LST, risk distribution) |
| GET | `/api/heatmap?city=bengaluru` | GeoJSON heatmap (optional `&risk=Critical` filter) |
| GET | `/api/feature-importance?city=bengaluru` | XGBoost feature importances + model accuracy |
| GET | `/api/mitigation/<risk_level>` | Mitigation suggestions (Low/Moderate/High/Critical) |
| POST | `/api/predict` | Live prediction from XGBoost model |
 
**Predict endpoint example:**
```json
POST /api/predict
{
  "city": "delhi",
  "lst": 38.5,
  "ndvi": 0.12,
  "ndbi": 0.18,
  "fvc": 0.08,
  "mndwi": 0.0,
  "ndmi": 0.0
}
```
Response:
```json
{ "heat_zone": 3, "risk": "Critical", "city": "delhi" }
```

## 🚀 Setup & Usage
 
### Prerequisites
- Python 3.9+
- Google Earth Engine account (only needed if re-extracting satellite data)
### Step 1 — Install Dependencies
```bash
pip install -r requirements.txt
```
 
### Step 2 — (Optional) Re-extract Satellite Data
Only needed if you want to regenerate the CSVs with fresh GEE data:
```bash
earthengine authenticate
python gee_extract.py              # all cities
python gee_extract.py bengaluru    # single city
```
 
### Step 3 — (Optional) Retrain Models
Only needed if you changed the CSV data or pipeline:
```bash
python pipeline.py                 # all cities
python pipeline.py bengaluru       # single city
```
 
> Skip Steps 2 and 3 if `data/` and `ml/models/` folders already exist.
 
### Step 4 — Start the Flask Backend
```bash
python app.py
```
API runs at: `http://localhost:5000`
 
### Step 5 — Open the Frontend
Open `index.html` in your browser. Select a city and click **Analyze**.

## 🔍 Predict Zone Feature
 
The **Predict Zone** page lets you enter custom satellite-derived values and get a live risk prediction from the trained XGBoost model:
 
1. Select a city
2. Enter LST, NDVI, NDBI, FVC values (or use the Quick Fill presets)
3. Click **Run Prediction**
4. Model returns: Risk Level (Low/Moderate/High/Critical), Heat Zone number, and description
This is the only page doing live ML inference — all other pages show pre-computed data.
